# Mapant Germany webapp

The map viewer at [mapant.orienteering-allgaeu.de](https://mapant.orienteering-allgaeu.de): a static
site built with [Vite](https://vite.dev/) and [MapLibre GL JS](https://maplibre.org/), deployed to
GitHub Pages by `.github/workflows/webapp.yml` on every push to `main`.

## Development

```bash
npm install
npm run dev         # dev server with hot reload
npm run typecheck   # tsc --noEmit
npm run build       # -> dist/
npm run preview     # serve dist/ on http://localhost:4173
npm test            # Playwright smoke tests (run `npm run build` first)
```

The first test run needs the browser: `npx playwright install --with-deps chromium`.

| `src/vector/` | the map in a rectangle as features, from the deepest tiles; the feature groups an export picks from |
| `src/render/` | draws those features in the ISOM style onto a PDF page or a canvas |
| `src/ocd/` | OCAD export (loaded on demand) |
| `src/i18n.ts`, `src/i18n/*.ts` | DE/EN strings, applied via `data-i18n` attributes |
| `src/ui/*.ts` | navbar, layer panel, PDF and OCD panels, draw toolbar, share button, zoom hint |
| `public/places.geojson` | town names overlay (generated, committed) |
| `public/states.geojson`, `public/state-labels.geojson` | the federal states' outlines and label points, for the shading (generated by `scripts/fetch-states.sh`, committed) |

The about page renders the repository's root `README.md` – or `README.de.md` when German is selected –
imported with Vite's `?raw`. The screenshots those files link to are served from `../img` by a small
plugin in `vite.config.ts`.

## PDF export

`src/pdf.ts` draws the print area as a vector page through [jsPDF](https://github.com/parallax/jsPDF)
(loaded on demand, with the renderer – together they are larger than the rest of the app).

* A4, portrait or landscape, at 1:4000 / 1:7500 / 1:10 000 / 1:15 000.
* The orienteering map is PDF paths, read from the archive's deepest level (`src/vector/area.ts`,
  the same reader as the OCD export) and drawn by `src/render/isom.ts` in isom-maplibre's style: its
  layers in their order, filters and paint properties evaluated by MapLibre's own expression code
  (`@maplibre/maplibre-gl-style-spec`). What a GPU would do is done with paths: each style layer is
  one path and one fill or stroke, fill patterns are their stripes clipped to the areas, the
  depression symbol is its stroke. Sharp on any printer, and a 1:10 000 page is some 8 MB rather than
  the 28 MB of a 600 dpi raster.
* Symbol sizes are ISOM's on paper: 100 % at 1:15 000, 150 % at 1:10 000 and the larger scales.
  isom-maplibre draws ISOM's 1:10 000 sizes at zoom 15 and scales them with the ground, as a screen
  map should; the page evaluates it at the zoom that gives the paper sizes (`styleZoom()`), whatever
  the latitude.
* Areas are kept whole across tile borders, buffers included: an area drawn twice in the same place
  looks like one, while two that merely abut would show a hairline seam in most PDF viewers. They are
  filled with the nonzero rule, which joins the copies and keeps the holes.
* Town names and drawings are text and paths too, in the built-in Helvetica (Latin-1; other letters
  lose their accents). Town names collide as on the map, the bigger place first.
* The hill shading, a raster by nature, is the one image: rendered by an off-screen MapLibre map at
  200 dpi (150 where the browser's canvas is small) with the terrain read at the paper's density, and
  laid over the map with transparency. MapLibre reports a map finished (`idle`) only after a frame,
  and a last request that fails does not ask for one; the export gives that map another frame while
  it waits, or it could wait forever.
* The scale is exact: the page's ground extent is derived from the paper size and corrected for the
  local Web Mercator distortion, so a ruler on the print agrees with the stated scale.
* A footer strip carries the scale and the copyright notices of the layers that were printed.

## The orienteering map

The map is drawn from the PMTiles archives mapant-nf publishes (`map/mapant.pmtiles`), one per
federal state, read with HTTP range requests from an R2 bucket served at `mapant-tiles.orienteering-allgaeu.de` (`MAPANT_TILES_BASE` in
`src/archive.ts`, each state's file name in `src/states.ts`), in the ISOM 2017-2 style of
[isom-maplibre](https://github.com/MetsaApp/isom-maplibre).

* **The states are one map to the style.** There is one vector source, served by the `mapant-tiles`
  protocol: `fetchTile()` asks each archive whose header bounds and zooms hold the tile. A tile only
  one archive has is passed on as it is; a tile on a border between two -- each holding its side,
  buffer included, as two parents' copies of a tile do in mapant-nf -- is merged by
  `mergeTiles()` in `src/tilemerge.ts`. The PDF and the OCD export read through the same function.
  An archive whose header cannot be read -- not uploaded yet -- is left out with a warning.
* **Nothing waits for the archives.** The bucket answers range requests slowly (it is not cached at
  Cloudflare's edge), so the map is built for the zooms mapant-nf cuts (`ARCHIVE_ZOOMS`, 10–15; an
  archive whose header says otherwise is reported in the console) and starts at once. An archive's
  header is read only when a tile within its state's `reach` (`src/states.ts`: the outline's box
  plus 0.1° for the border tiles, checked by `tests/states.spec.ts`) is asked for, and for the
  opening view already while the map is set up (`prefetchArchives()`). A visit to Bavaria reads
  Bavaria's header only. A state's LiDAR credit appears once its header is in.
* **Tile workers.** MapLibre parses tiles in a single worker outside Safari; `src/map.ts` asks for
  half the cores, two to four. The tiles are heavy in rocky ground -- one z14 tile of the Allgäu is
  3.7 MB, nine tenths of it cliff segments -- and a screenful is parsed side by side. The heaviest
  single tile still bounds the wait, since one tile cannot be split between workers: the lasting
  fix is smaller tiles from the pipeline.
* **Below the orienteering map's zooms each state is shaded by its LiDAR**: rendered, free, against
  a fee, or not available (`status` in `src/states.ts`, following Jens Wiesehahn's
  [overview](https://wiesehahn.github.io/posts/lidar_availability/)), between the basemap's ground and its
  labels. Each state is labelled directly with its name and status, in the status colour and the
  current language, in place of the basemap's own state names.
* The footer credits the LiDAR of each state whose archive the view touches.
* The OCD export is georeferenced in the CRS of the state under the map centre (`crsAt()`):
  EPSG:25833 for Brandenburg, Sachsen and the other eastern states, EPSG:25832 elsewhere.

* **The style is a fork of isom-maplibre** (branch `fix/iof-colour-order` on top of upstream
  `3c8ee09`), packed into `vendor/metsa-isom-maplibre-0.1.1-mapant.3.tgz` so the build needs nothing
  outside this repository. It stacks the symbols in the IOF colour order for ISOM 2017-2 ("IOF Map
  Specifications – Printing and Colour Definitions", 2022, §7), where upstream 0.1.0 did not: olive
  (520) above the greens, streams above the contours, lake fill below wide roads and large buildings.
  Contours stay above lakes, as in the standard; karttapullautin leaves them out under lakes instead
  (`contour_mask`). The fork also keeps every symbol sharp at any zoom: the depression (111) and
  slope tick are signed distance fields (`isomImage()` in the package; MapLibre draws them like
  text), and the fill patterns come once per zoom at their true ground spacing. To update it, rebuild the fork (`go generate ./... && npm run build && npm pack`)
  and replace the tarball.
* **The archive is in the style's schema**: a layer per table (`contours`, `vegetation_areas`,
  `paths`, …), each feature with its ISOM 2017-2 `isom_code` (`"403.000"`), 512 px tiles. The style's
  layers are used as they are; `src/isomstyle.ts` only points all of them at the one source, where the
  style expects one source per table.
* Below z13 the style draws its overview pass, from the same source. The archive's shallowest level is
  an overview without contours; below it only the OpenFreeMap basemap is shown (`src/basemap.ts`)
  (`MAP_MIN_ZOOM`, the archives' shallowest zoom). At the map's zooms the basemap is shown only outside the states that have an
  orienteering map: its tiles are fetched through the `basemap-tiles` protocol, which skips a tile
  lying wholly inside such a state's outline (`isMapped()` in `src/archive.ts`) -- even where the
  state's archive does not reach, which is left empty -- so nothing is fetched from openfreemap.org
  there. Where a tile straddles a state border, the map's white paper (`coverage`) covers its part.
* Private property (ISOM 520, olive) can be switched off in the layer menu (`p` in the share link,
  on by default); the PDF follows the switch.
* Fills draw polygons only and lines draw lines only: MapLibre would otherwise fill an open line, and
  trace the edges a polygon was clipped at.
* The style's background is not used: the white paper is the archive's `coverage` layer, the footprint
  of the tiles that were rendered, so the rest of the viewport stays empty.
* The style's pattern and symbol images are rasterised from isom-maplibre's SVGs as MapLibre asks for
  them, at the screen's or the print's pixel ratio.
* The bucket has to send CORS headers, including `Range` and `ETag`, for any origin that serves the
  app other than the bucket itself (the GitHub Pages domain, `localhost` during development).
* **Local testing**: `npm run dev:local` links each state's newest mapant-nf result
  (`processing_pipeline/<state>/results_*/map/mapant.pmtiles`) into `public/tiles/` under the name
  `src/states.ts` gives it (`scripts/link-local-tiles.sh`; a local Bavarian result stands in for the
  published state -- `--no-bayern` keeps the published one) and starts the dev server with `VITE_MAPANT_LOCAL_TILES=/tiles/`:
  each state's archive is read from there if it is there, and from the bucket otherwise. Vite's dev
  server answers range requests. The bucket's CORS rules admit `localhost:5173` and `:4173` only.
* `VITE_MAPANT_TILES` replaces the bucket altogether, for a build pointed at another host.
* A new state's archive goes into the bucket under the name in `src/states.ts` (`mapant-bayern-v2.pmtiles`,
  `mapant-nrw.pmtiles`, ...); a state only gets an `archive` there once its file is in the bucket.

## OCAD export

A page's rectangle can be saved as an editable OCAD file, as a starting point for someone who is
going to survey the area -- from a panel of its own (the "OCD" button), which works as the PDF's
does. `src/ocd/` does the whole conversion in the browser; there is no
backend and no WebAssembly, because an A4 page is a few dozen vector tiles and a few megabytes of
`DataView` writes.

* **What goes in** is chosen by feature group (`src/vector/groups.ts`): from the LiDAR vegetation,
  contours and form lines, knolls and depressions, cliffs; from OpenStreetMap water, roads and
  paths, other man-made features, private property. Every feature of the archive is in one group, so
  with all ticked the file holds everything the map shows (and a few things the style does not draw,
  such as fences, 518).
* **Background map.** The same groups can be drawn into a background map instead or as well. An OCD
  file cannot hold an image -- a background map is a file of its own that the OCD names and places,
  in a parameter string of type 8 -- so the export renders the groups in the map's style (the PDF's
  renderer, onto a canvas) into a PNG aligned with the file's paper, which is the UTM grid, at
  300 dpi, and writes beside it a world file (`.pgw`, UTM metres) for programs that read one. The
  OCD's type-8 string names the image without a folder and places it as Mapper writes it for OCD 11+
  (`x`/`y` its centre in millimetres of paper, `u`/`v` millimetres per pixel), so OCAD and Mapper
  open it with the file. The three come in a zip; without a background map, the OCD file alone.
* The data comes from the same archive the map is drawn from (`src/archive.ts`), read through
  `src/vector/area.ts`, which the PDF uses too. `src/ocd/config.ts` holds the template URL and the
  target coordinate system.
* It always reads the **deepest** zoom, the only level that carries the map as karttapullautin
  rendered it. Every level above it is deliberately generalised for the screen -- form lines and
  knolls left off, the vegetation traced from a coarser grid, the cliff hatching sampled -- which is
  right for an overview and wrong for a map to survey from.
* A tile that does not decode as a vector tile costs its own square and no more.
* Tiles carry a buffer of their neighbours' geometry, so every feature is first clipped to its own
  tile square -- the pieces from adjacent tiles then abut instead of overlapping -- and the line
  pieces of a feature that met at a border are stitched back into one line (`src/vector/geometry.ts`).
* Every feature carries its ISOM 2017-2 symbol as `isom_code`; mapant-nf has already translated the
  OpenStreetMap shapes from ISOM 2000 with OpenOrienteering Mapper's crosswalk. `src/ocd/isom.ts`
  only spells it the template's way (`"521.001"` is 521.1) and splits what the style draws as one by
  geometry: a lake (301.1) and its bank line (301.4). An impassable cliff is the plain top line,
  201.3, rather than 201 with its tags: karttapullautin gives the top edge without the side of the
  drop, and the tags are the mapper's to add, as on 202, which is a plain line already.
* A slope line (karttapullautin's tick from a depression's contour downhill) becomes the rotatable
  point 101.1 at the contour, turned on paper to point down the tick: the template draws the symbol
  pointing north, so its angle is the tick's direction from east less 90°.
* The file is written by appending to `public/templates/isom2017-2_10000.ocd`
  (`src/ocd/ocdwriter.ts`). An OCD object can only reference a symbol defined in the same file, so
  the template supplies the symbol set and colour table; the writer keeps its bytes verbatim,
  repoints the georeferencing string, and appends object index blocks and objects. That is also why
  a code with no symbol in the template is dropped with a warning rather than written as a
  reference to nothing, which OCAD reports as a damaged object.
* The result is georeferenced in the LiDAR's own projected system -- that of the state under the
  map centre, ETRS89 / UTM zone 32N or 33N (`crsAt()` in `src/states.ts`) -- so coordinates are
  the surveyor's own rather than Web Mercator's stretched ones.

`tests/ocd.spec.ts` exports a page from a small real archive and reads the result back with
[ocad2geojson](https://github.com/perliedman/ocad2geojson) -- a different implementation of the
format -- checking the version, that every object references a defined symbol, that the
georeferencing lands in the right UTM range, that unticked groups stay out, and that a background
map comes as a zip whose OCD names the image.

An A4 at 1:10 000 over this terrain is around 220 000 objects and 30 MB, written in some five
seconds; at 1:4000 it is 65 000 objects in under two. Two thirds of either is the cliff hatching,
which karttapullautin draws as individual ticks.

The template was exported from OpenOrienteering Mapper's ISOM 2017-2 symbol set, which is GPLv3;
so is this app (see [Licence](#licence)).

## Drawings in the share link

Finished sketches are snapped onto the ~10 cm grid the URL stores (`src/drawings.ts`), so the length or
area shown on screen is exactly the one a shared link reproduces. `tests/drawings.spec.ts` pins that
round trip.

## Data sources

Zoom levels as in the share link (256 px tiles, OpenStreetMap's convention).

| Layer | Source | Zoom levels |
| --- | --- | --- |
| Background | OpenFreeMap vector tiles (OpenMapTiles schema), its Liberty style vendored in `src/basemap/liberty.json` (`npm run fetch-basemap`) | every zoom outside the states with an orienteering map, below the map's zooms inside them (tiles wholly inside such a state are not fetched there); not on a print |
| Orienteering map | mapant-nf vector tiles (`{z}/{x}/{y}.pbf`) on R2, in isom-maplibre's ISOM 2017-2 style | 12–16 (overzoomed to 23) |
| Hill shading | Mapterhorn terrarium DEM, MapLibre's hillshade layer (shadows only) | 0–16 (overzoomed above) |
| Town names | OpenStreetMap via Overpass | cities and towns 12+, villages 13+ |

## Refreshing the state outlines

```bash
scripts/fetch-states.sh   # Natural Earth admin-1, rewrites public/states.geojson
```

## Refreshing the town names

```bash
npm run fetch-places   # queries Overpass, rewrites public/places.geojson
```

Commit the result – the build and the site never talk to Overpass. It covers the states that have a
map archive (`MAPPED_STATES` in the script; keep it in step with `src/states.ts`) and is currently
~14,000 places (1.8 MB); if that ever gets too heavy, drop `village` from the query
in `scripts/fetch-places.mjs`.

## Deployment notes

Pages must be configured once in the repository settings: **Source = GitHub Actions**, and
**Custom domain = mapant.orienteering-allgaeu.de** with a `mapant` CNAME record pointing at
`grst.github.io.` in DNS.
